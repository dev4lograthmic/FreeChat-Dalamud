# Transport and connection

## 1. Endpoint

```text
wss://<host>:<port>/ws
```

- Default port: `14777`; use the value shown in the plugin UI and deep link.
- Default bind address: `127.0.0.1`.
- With LAN enabled, the server binds `0.0.0.0`; use the LAN address shown by the
  plugin.
- v1 supports WSS only; plaintext `ws://` is not supported.
- Browser clients are out of scope for v1.

## 2. TLS and pinning

The server uses a self-signed ECDSA P-256 certificate with TLS 1.2/1.3.

Clients **must** pin the server public key during the TLS handshake:

```text
public_key = 0x04 || X(32) || Y(32)   // X9.63 uncompressed, 65 bytes
fingerprint = SHA-256(public_key)     // 32 bytes
fp = lowercase hex(fingerprint)       // 64 hex chars
```

- Compare the **raw public-key fingerprint**, not the certificate SHA-256 or
  serial number.
- `fp` comes from the plugin pairing deep link or the **Pairing** tab.
- On mismatch, abort immediately. Do **not** send `ClientHello` or the pairing
  code.
- Certificate rotation with the same key keeps the pin stable; rotating the
  key requires clients to update the pin.

## 3. WebSocket subprotocols

The HTTP Upgrade must offer:

```http
Sec-WebSocket-Protocol: freechat.v1.protobuf
```

For debugging:

```http
Sec-WebSocket-Protocol: freechat.v1.json
```

- `freechat.v1.protobuf`: default; binary frames carrying an `Envelope` in
  protobuf.
- `freechat.v1.json`: text frames carrying an `Envelope` as proto3 JSON. It is
  accepted only when `Enable JSON debug transport` is enabled in the plugin.
- The server selects the first supported subprotocol and echoes it in
  `101 Switching Protocols`.
- If no offered subprotocol is supported, the server returns HTTP `400`.

### JSON encoding

- One WebSocket text message = one `Envelope`.
- Field names use lowerCamelCase (`request_id` -> `requestId`).
- `int64`/`uint64` are strings, e.g. `"42"`.
- `bytes` are base64.
- Enums use names, e.g. `"CHAT_CHANNEL_SAY"`.
- `google.protobuf.Timestamp` uses RFC3339, e.g.
  `"2026-10-20T12:34:56.789Z"`.
- JSON and protobuf carry the same fields. JSON is disabled in production by
  default.

## 4. Envelope and framing

Every message is wrapped in:

```proto
message Envelope {
  string request_id = 1;
  oneof payload { ... }
}
```

Rules:

- One `Envelope` per WebSocket message.
- Do not concatenate multiple envelopes into one message.
- `request_id` is generated by the client and echoed by the server.
- Push messages (`ChatEvent`, `Pong`, `SessionEnded`, `ServerShutdown`, etc.)
  may omit `request_id`.
- `request_id` should be unique per connection; UUID/ULID is recommended.
- Ignore unknown oneof fields and unknown enum values; clients may fall back to
  `*_UNSPECIFIED`.

## 5. Default limits

These are implementation defaults; some are configurable in the plugin:

| Item | Default |
|---|---|
| Maximum WebSocket message | 1 MiB |
| HTTP request headers | 8 KiB |
| Maximum clients | 32 |
| Send rate limit | 4/second, burst 4 |
| Send queue | 32 per connection |
| Backlog | 5000 events / 32 MiB |
| WebSocket handshake timeout | 5 seconds |
| `ClientHello` timeout | 5 seconds |
| Pairing confirmation timeout | 60 seconds |
| Challenge response timeout | 10 seconds |
| Suggested first `Subscribe` timeout | 10 seconds |
| WebSocket keepalive | 20 seconds |

Messages above the size limit close the connection with `1009`.

## 6. Keepalive

- WebSocket keepalive is maintained by `KeepAliveInterval`.
- Application-level ping:

```proto
message Ping {
  bytes nonce = 1;
  google.protobuf.Timestamp client_time = 2;
}
```

The server replies:

```proto
message Pong {
  bytes nonce = 1;
  google.protobuf.Timestamp server_time = 2;
}
```

Clients should match `Pong` by nonce and may estimate latency from the
timestamps.

## 7. Closing

- Normal close: `1000`.
- Server stop/plugin unload: `SessionEnded` or `ServerShutdown`, then close.
- Authentication failure: `AuthError`, then close `4001`.
- Device revoked: `4003`.
- Protocol/encoding mismatch: `4004`.
- Slow consumer: `4005`.
- Message too large: `1009`.
- Internal error: `1011`.

See [Errors](errors.md) for the complete list.

## 8. Reconnect

- On `SessionEnded` or `ServerShutdown`, stop the current subscription and
  close the socket.
- Reconnect using the saved `device_id`, device private key, and `server_id`.
- If `Welcome.session_id` changed, clear the old session's `last_sequence`.
- For history, send `ReplayRequest` or `Subscribe` with `from_sequence`.
